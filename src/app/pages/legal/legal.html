Grimoire is hosted under the ALL-INKL PrivatPlus plan by ALL-INKL.COM – Neue Medien Münnich. A data processing agreement has been concluded with the hosting provider. The hosting provider generally creates two backups of webspace files: one up to approximately two weeks old and another up to approximately four weeks old. 3. Registration and sign-in with Firebase

We use Firebase Authentication for user accounts and Firebase Realtime Database for usernames. Email addresses, usernames, user IDs and technical sign-in data are processed. Passwords are transmitted to Firebase Authentication; they are not stored in our Realtime Database. This information is needed to set up and use an account. Chess games saved voluntarily are stored as PGN together with user-chosen folder and game names under the user ID in the Realtime Database and associated with the respective account.

User accounts and profiles are generally stored until the account is deleted. There is no automatic deletion due to inactivity. In the signed-in main menu, irreversible deletion can be initiated under “Settings” → “Delete account” after reconfirming the current password. This deletes the profile and all saved folders and games from the Realtime Database, followed by the account in Firebase Authentication. If the subsequent account deletion fails, games already deleted cannot be recovered; the application displays the error and allows another attempt. Privacy enquiries can still be made by email. Please do not send passwords by email. Signing out alone does not delete the account.

According to Google's published information, Firebase Authentication processes data exclusively in data centres in the USA. Logged IP addresses are retained there for several weeks. After account deletion is initiated, Google states that the remaining authentication data is removed from live and backup systems within 180 days. Google states that Firebase Realtime Database retains IP addresses and user-agent information for a few days unless longer storage has been selected.

Optional daily automatic backups of the Realtime Database are not enabled for this project. These are distinct from the service provider's internal backup and deletion procedures.

4. Local storage and other services

Firebase Authentication stores the sign-in state in the browser, including in IndexedDB, so the session can be restored after the browser is closed and reopened. Signing out ends the active session on this device and removes the stored sign-in state.

Firebase Realtime Database stores technical connection information in local browser storage, including a database server address and, where applicable, an indication of a failed WebSocket connection attempt. Firebase also stores technical heartbeat information, such as a date and details of the Firebase SDK version used, in IndexedDB. These entries support the operation of Firebase services and may remain after signing out.

Firebase updates or partially removes the technical entries as needed. We are not aware of a fixed general deletion period. You can delete locally stored website data in your browser settings; this may also end an existing session. The entries may be created again when you use the website again.

Firebase Analytics is not initialized in the application code. Advertising and additional tracking services are not planned. [Before publication, check the legal bases for processing and accessing browser storage, as well as any required consent procedure.]
