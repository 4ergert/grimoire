2. Hosting and server logs

Grimoire is hosted under the ALL-INKL PrivatPlus plan by ALL-INKL.COM – Neue Medien Münnich. A data processing agreement has been concluded with the hosting provider. When the website is accessed, technically necessary connection data is processed, including the IP address, time and target of the request, and browser and device information. This serves to provide and securely deliver the website. The legal basis is Article 6(1)(f) GDPR; our legitimate interest is the reliable and secure operation of the website.

In the hosting provider's KAS administration, “Es werden keine Logs erzeugt” (“No logs are created”) is selected. Accordingly, no operator-configured access logfiles are created in the /logs/ directory. The interface shows a seven-day logfile retention period; this setting applies if logfile creation is enabled and does not mean that logfiles are currently being stored. Connection data still needs to be processed to deliver the website.

According to the hosting provider, independently of this setting, it logs access for administrative purposes with full IP addresses, including to detect and defend against cyberattacks. The operator does not have access to these logs. According to the hosting provider, the data is deleted no later than seven days after collection. The processing serves the security of the hosting operation and is based on Article 6(1)(f) GDPR; the legitimate interest is protecting the website and hosting infrastructure against attacks.

The hosting provider generally creates two backups of webspace files: one up to approximately two weeks old and another up to approximately four weeks old. These webspace backups are not backups of user accounts and games stored in Firebase. The operator does not create additional backups of personal user data.

3. Registration and sign-in with Firebase

We use Firebase Authentication for user accounts and Firebase Realtime Database for usernames. Email addresses, usernames, user IDs and technical sign-in data are processed to create and manage an account and enable sign-in. Passwords are handled by Firebase Authentication and are not stored in our Realtime Database. If you choose to save chess games, the folder and game names and PGN files you provide are processed so you can save, view and delete them through your account. The legal basis for providing the account and these requested features is Article 6(1)(b) GDPR, as this processing is necessary to perform the user agreement set out in the Terms of Use. Data needed for a feature is required to provide that feature; saving games is optional.

Each username is reserved in the Realtime Database by storing your user ID under the lowercase form of the name, so that every name is unique. Signed-in users can look up an individual name to see whether it is taken; this also reveals the user ID stored for it. The database does not allow listing all reserved names. Email addresses are not stored in the Realtime Database.

After registration, and whenever you request it from the main menu, the application asks Firebase Authentication to send a verification email to your email address. The email is sent through Google's infrastructure using the configured Firebase template in English and contains a link that returns you to grimoire.julian-hergert.de. Whether your address is verified is processed as part of your account data. Verification is required to use the account-based game features. The legal basis is Article 6(1)(b) GDPR.

Guest mode does not create an account, and the application does not store guest games in Firebase. Chess analysis and the moves of the computer opponent are calculated locally in your browser; the positions are not sent to a server. The connection data described in section 2 is still processed when the website is accessed.

User accounts and profiles are generally stored until the account is deleted. There is no automatic deletion due to inactivity. In the signed-in main menu, irreversible deletion can be initiated under “Settings” → “Delete account” after reconfirming the current password. This deletes the profile and all saved folders and games from the Realtime Database, followed by the account in Firebase Authentication. If the subsequent account deletion fails, games already deleted cannot be recovered; the application displays the error and allows another attempt. Privacy enquiries can still be made by email. Please do not send passwords by email. Signing out alone does not delete the account.

According to Google's published information, Firebase Authentication processes data exclusively in data centres in the USA. Logged IP addresses are retained there for several weeks. After account deletion is initiated, Google states that the remaining authentication data is removed from live and backup systems within 180 days. Google states that Firebase Realtime Database retains IP addresses and user-agent information for a few days unless longer storage has been selected.

Optional daily automatic backups of the Realtime Database are not enabled for this project. These are distinct from the service provider's internal backup and deletion procedures.

We use Firebase Authentication and Firebase Realtime Database as Google Cloud Platform services. According to Firebase Support, these services are governed by the Google Cloud Platform Terms of Service, and Google's Cloud Data Processing Addendum applies. Google says the applicable Terms of Service are accepted digitally when a project is created. The contracting Google entity depends on the billing address and whether the customer contracts as a business or an individual; it must be determined for this project using Google's contracting entity information. The project's recorded acceptance and CDPA status have not been independently verified for this draft. Google says these records and CDPA settings can be reviewed in Cloud Console under IAM & Admin → Privacy & Security (or Legal & Compliance).

The Realtime Database uses the europe-west1 region (Belgium). This does not mean that all Firebase services process data exclusively in the EU: according to Firebase Support, Firebase Authentication is a US-only service. Google's Firebase privacy information describes data locations, subprocessors and international transfer mechanisms, including the EU-US Data Privacy Framework and Standard Contractual Clauses. The current transfer mechanism applicable to each service, Google's contracting entity and certification scope, and any agreed contractual safeguards for this project still need to be verified before publication. The current Firebase subprocessor list is also available from Google.

4. Local storage and other services

Firebase Authentication stores the sign-in state in the browser, including in IndexedDB, so the session can be restored after the browser is closed and reopened. Signing out ends the active session on this device and removes the stored sign-in state.

Firebase Realtime Database stores technical connection information in local browser storage, including a database server address and, where applicable, an indication of a failed WebSocket connection attempt. Firebase also stores technical heartbeat information, such as a date and details of the Firebase SDK version used, in IndexedDB. These entries support the operation of Firebase services and may remain after signing out.

Firebase updates or partially removes the technical entries as needed. We are not aware of a fixed general deletion period. You can delete locally stored website data in your browser settings; this may also end an existing session. The entries may be created again when you use the website again.

The application also stores your display preferences in the browser's local storage: the selected board color theme (key grimoire.boardTheme) and, if you use the custom theme, the two square colors you picked (key grimoire.boardTheme.custom). These values are not personal data in themselves, are not sent to a server, and are only read by the application to restore your choice. They remain until you delete the website data in your browser settings.

Firebase Analytics is not initialized in the application code. Advertising and additional tracking services are not used. The browser storage described above is used only to provide the sign-in and display settings you request and is not used for analytics or advertising; therefore, no consent banner is shown.
